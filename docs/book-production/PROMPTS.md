# Prompts

Every prompt Volume sends to a model lives in `prompts/` as a versioned Markdown file. This page indexes them. The file format, variables and versioning rules are in `prompts/README.md`; the models each stage uses are in `config/models.defaults.json`.

39 prompts. Version 1 of each was written on 4 October 2026 for fully automatic mode: the AI writes the whole book in the first person from the author profile, inside the house style (`config/house-style.json`) and the honesty guardrails. The version 2 files (5 October 2026) put the banned list in its own block. The round 5 versions (5 October 2026, after a live book) add the profile facts block (`{{profile.facts}}`) with a hard rule never to state personal facts, relationships, history or credentials the profile does not hold, the grouped used-already list, word targets for the introduction and conclusion, the book word target and book-type structure in the blueprint, personal claims in `checks.claims`, warnings in `checks.summarise-and-ledger`, the cover concept count, and the new `writing.extend-section`. The round 6 versions (5 October 2026, after live run 3) stop the writing prompts inventing the author's past experience or conversations, state the author's background at most once in the body (`{{profile.factsUsedIn}}`), never name a firm as a scam or regulated without a research source, add dated prices (`{{book.datedPrices}}`, `{{book.checkedMonth}}`) and let pages promise dated prices only when the app's check passed (`{{book.pricesCheck}}`); they also tighten resources and the glossary, judge each section against its own plan and catch references to scenes never written (`checks.consistency`), skip composite-story lines and add named-firm claims (`checks.claims`), add page titles to research source notes, add scaffolding openers to the style rewrite, and keep marketing to what the written chapters teach. Older versions stay in place for books pinned to them.

## Pipeline order

1. Research: `research.title-research` (web search; sources only from `url_citation` annotations).
2. Titles: `titles.topic-directions`, then `titles.title-options`.
3. Blueprint: `blueprint.blueprint`; any field again with `blueprint.regenerate-part`.
4. Writing, per chapter: `writing.chapter` (and one `writing.extend-section` pass when a section comes back under 85% of its word target), then `checks.summarise-and-ledger` (summary and used-already ledger for the next chapter), then code checks and `checks.consistency` and `checks.claims`. Front and back matter: `writing.introduction`, `writing.conclusion`, `writing.front-matter`, `writing.back-matter`. Editor: `writing.rewrite-selection`, `writing.weave-note` and `writing.expand-note` (author notes woven in, or expanded into a new subsection).
5. Editing: `editing.structural`, `editing.line-edit-uk`, `editing.voice`.
6. Matter and metadata: `matter.amazon-description`, `matter.keywords-categories`, `matter.back-cover`.
7. Covers: `cover.cover-brief`, then `cover.cover-image` writes the text-free prompt the image model receives.
8. Marketing: `marketing.tiktok-scripts`, `marketing.instagram-captions`, `marketing.launch-email`.
9. Fiction and workbooks (phase 6): the app picks the prompt by book template with `taskForTemplate` in `packages/ai`. Fiction books run `blueprint.blueprint-fiction` (with the story bible, D-043), `blueprint.regenerate-part-fiction`, `writing.chapter-fiction` (scene breaks as `***`, no subheadings or takeaways) and `writing.extend-section-fiction` (deepens scenes, never adds a heading); the story bible is sent once, as `{{storyBible}}`, and left out of `{{blueprint}}`; workbooks run `blueprint.blueprint-workbook` (2 to 4 planned exercises per chapter) and `writing.chapter-workbook` (the block dialect of D-042). Every other template keeps `blueprint.blueprint` and `writing.chapter`. `checks.summarise-and-ledger` v5 logs fiction characters and settings, and `checks.consistency` v4 checks fiction against the story bible and workbook exercise blocks.
10. Picture books (phase 7): `children.picture-book-story`, then `children.scene-prompts`, then `children.character-reference`. The app paints one reference image per main character, then one 2:1 image per spread with those references and a fixed seed where the model takes one (D-045).

## Stages that share a model

- `checks.summarise-and-ledger` runs on the `summarise` stage model (small), not the `checks` model, so the owner can tune them apart.
- `cover.cover-image`, `children.scene-prompts` and `children.character-reference` run on the `cover_brief` text model. Their `imagePrompt` output is what the `cover_image` stage (the image model, `POST /api/v1/images`) receives.
- `children.picture-book-story`, `writing.chapter-fiction` and `writing.chapter-workbook` run on the `writing` model; `blueprint.blueprint-fiction` and `blueprint.blueprint-workbook` on the `blueprint` model.

## What changed from the drafts

- No ISBN is ever generated (the drafts asked for a "realistic ISBN"). The ISBN appears only if the owner entered one.
- The copyright year is filled automatically (the drafts fixed it at 2025).
- The introduction no longer includes testimonials (step 7 of the drafts' introduction formula): the author's own reason for writing replaces it.
- "Readers never suspect AI" is dropped: the prose is natural, and the KDP AI disclosure is set to AI-generated (KDP fact 5.5).
- Quote and "did you know" hooks use only quotes the owner supplied or facts from cited research sources; otherwise the chapter opens with a scene.
- Channel-specific calls to action in the children's drafts ("follow our page") are now an optional `{{cta}}` the owner fills.
- About the author is never written by AI: it is the profile bio word for word.

## How to add or change a prompt

1. Never edit a released version. Copy `prompts/<folder>/<name>.v<N>.md` to `.v<N+1>.md`.
2. Set `version` in the front matter, change the text, and add a `# Changes` section at the bottom saying what changed and why.
3. Keep the front matter complete: `id`, `version`, `stage`, `tier`, `inputs` (every `{{variable}}` the body uses), `output`, `derived_from`, `guardrails`.
4. KDP numbers only through `{{kdp.*}}` variables; banned phrases only through `{{houseStyle.bannedPhrases}}`. If a prompt must quote banned words on purpose, wrap them in `<!-- house-style:off -->` and `<!-- house-style:on -->`.
5. A new prompt also needs: its id in the stage's `prompts` list in `config/models.defaults.json`, a mock fixture in `packages/ai/test/fixtures/`, and a row in the table above.
6. Check before you hand over: the front matter parses as YAML, every variable in the body is in `inputs`, and the file has no em dashes and no banned phrases outside the marked blocks.
7. Add a line to `CHANGELOG.md`. Books pinned to an older version keep using it.

## Humanizer revision, 6 October 2026

The latest versions of all 32 prompt IDs apply humanizer 3.0.0 principles. Guidance is stored in the project files, without a runtime dependency on a machine-specific skill path. Reader-facing prose keeps author voice and supported facts; internal checks/repair preserve quoted evidence and their output contracts. Automatic style repair keeps its targeted scope and runs only on the existing triggers. No extra model call was added. Historical versions and explicit pins remain supported. This is editorial guidance, not a guarantee of live writing quality or a change to AI disclosure.
